Two test layouts coexist here: flat files directly under `tests/` (older, e.g. `test_plugin_ribbon.py`, `test_host_ai.py`), and `tests/unit/{plugin,host}/` (current convention, mirrors `src/karcytics_sdk/{plugin,host}/` module-for-module, including `tests/unit/plugin/rendering/` mirroring `plugin/rendering/`). Put a new test for `src/karcytics_sdk/<pkg>/<module>.py` at `tests/unit/<pkg>/test_<module>.py`, not in the flat top-level directory.

`conftest.py` provides a session-scoped, autouse `qapp` fixture (one `QApplication` for the whole run, `QT_QPA_PLATFORM=offscreen`) and an autouse `_reset_plugin_config_registry` fixture — `PluginConfig` memoizes one instance per `plugin_id` per process, so tests that construct configs for the same `plugin_id` would otherwise leak state across tests without this reset. Don't add a competing `QApplication()` call or per-test Qt app fixture.
