Author-facing plugin API. A few modules carry load-bearing context not obvious from a quick read — check a file's own docstring before assuming its purpose from its name, especially these:

- `runtime_services.py` — the *real* import location for `task_scheduler`, `event_bus`, `diagnostics`, `tutorial_manager` inside an isolated (`process_model = "isolated"`) plugin process. These are not proxies or shims for the Hub's `karcytics.core.*` equivalents — an isolated plugin's `.venv` never has `karcytics` importable at all, so this module is where those names genuinely live for that process.
- `daemon.py` / `ui_daemon_runtime.py` — the msgpack/IPC machinery for an isolated plugin's worker and UI processes. `ui_daemon_runtime.py`'s `run()` is generic across every isolated plugin (frame transport, ready handshake, dispatch, window-close detection); a plugin's own `ui_daemon.py` only does plugin-specific setup and hands `run()` a zero-arg panel factory. Don't duplicate that generic logic in a plugin repo.
- `manifest.py` / `manifest_parser.py` — parses `[tool.karcytics.plugin]` from `pyproject.toml` (or legacy `manifest.json`) into `PluginManifest`; `VALID_PROCESS_MODELS = ("in_process", "isolated")` is the full set.
- `rendering/pipeline.py` — splits plot compute (parallelizable, pure numpy/pandas, no rasterization calls) from rasterization (must run under `RasterLock`) into `RenderComputeStage` (an `AnalysisBase` subclass — reuses the standard `AnalysisWorker`/`ITaskScheduler.submit()` path) and a separate rasterize stage. A render-oriented `AnalysisBase.run()` should follow this split rather than computing and drawing in one call.
- `theme_fallback.py` — provides `Colors`/`theme_manager` when `karcytics.ui.theme` isn't importable (any isolated plugin, or an in-process one running standalone in CI). `base.py`'s `try/except ImportError` at import time is the pattern to follow if you add another module that needs live theme values.

`cyto_character.py`, `cyto_costumes.py`, `tutorial_overlay.py`, `course_complete_overlay.py`, `academy_driver.py` are vendored, carefully-tuned animation/coaching-UI widgets (ruff complexity rules are relaxed for them in `pyproject.toml` — see the comment there) — don't refactor their branching/magic numbers for lint compliance; that risks changing tuned visual behavior for no functional gain.
